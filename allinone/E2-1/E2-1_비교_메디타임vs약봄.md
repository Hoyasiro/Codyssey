# 선정안(메디타임) vs 제안안(약봄) 비교 및 보완 포인트

## 1. 두 안 비교

| 항목 | 메디타임 (선정안) | 약봄 (제안안) |
|---|---|---|
| 핵심 문제 | 약마다 복용 간격·피해야 할 음식이 달라 기억하기 어려움 | 같이 먹으면 안 되는 약이 섞여도 본인이 모름 |
| 대상 약 | 처방약 + 영양제 + 호르몬제 | 처방약 위주 |
| 결과물 | 하루 복용 시간표 + 약별 주의 음식 | 위험 조합 알림 + 쉬운 설명 |
| 안전장치 | 약사 확인 단계 | "약사·의사에게 확인하세요" 안내 |
| AI 기술 | **명시 안 됨** (규칙 대조 중심) | OCR + RAG + 음성 대화 |
| 근거 통계 | 2020년 상반기 자료 | 2025년 자료 (144만 명, 참여율 0.8%) |
| 데이터 출처 | "공공 의약품 정보" (구체 API 없음) | 식약처·심평원 공공 API |
| 보호자 | 복용 기록 공유 | 위험 시 보호자 알림 |

**메디타임이 더 나은 점**: 음식·영양제까지 다뤄 차별점이 더 구체적임. 음식 예시표가 있어 발표에서 바로 이해됨. 약사 확인 단계로 안전성 설명이 탄탄함. 역할 분담과 4주 일정이 이미 짜여 있음.

**약봄에서 가져올 점**: AI 기술 구성, 최신 통계, 구체적인 공공 데이터 출처, 시스템 구성.

## 2. 미션 요건 대비 메디타임의 빈 곳

| 미션 요구 | 현재 상태 | 보완 |
|---|---|---|
| **AI가 서비스의 핵심이어야 함 (필수 요건)** | AI 언급 없음. 규칙 대조만으로는 일반 앱으로 보일 위험 | AI 4요소 추가: 약봉투·라벨 인식, 약물·음식 지식 추출(RAG), 시간표 최적화, 쉬운 말 설명 |
| AI 기술 적용 + 선택 이유 | 없음 | 기술별 선택 이유 표 추가 |
| 시스템 구성(다이어그램 권장) | 작동 흐름 텍스트만 | 구성도 추가 |
| 타겟 사용자·니즈 | 기획의도에 섞여 있음 | 주/부 타겟과 니즈를 따로 정리 |
| 차별점 | "확인되지 않는다" 한 줄 | 기존 서비스와 비교표 |
| 향후 발전 방향 | 활용방안에 일부 | 단계별 로드맵으로 정리 |
| 근거 최신성 | 2020·2021 자료 | 2025 자료로 교체 (144만 명, 65세 이상 82%) |

## 3. 결론
메디타임의 주제·기능·역할분담은 그대로 두고, **"AI가 핵심"이라는 필수 요건을 채우는 것**이 가장 중요한 보완입니다. 이 내용으로 기획안(`E2-1_기획안_메디타임.md`)과 발표자료를 새로 만들었습니다.
